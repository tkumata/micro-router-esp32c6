# Web UI 認証方式変更 設計

## 方針

- 認証は `WebUIManager.cpp` 内で完結させる。
- セッションはメモリ上の単一トークンで管理する。
- ブラウザには `Set-Cookie` でセッション cookie を返す。
- CSRF トークンは既存のグローバルトークンを継続利用する。

## 画面遷移

1. 初期 AP パスワードの間
   - `GET /` は AP パスワード変更専用画面を返す。
   - `POST /save_ap_password` のみ許可する。
2. AP パスワード変更後
   - `GET /login` でログイン画面を返す。
   - `POST /login` で AP パスワードを検証し、成功時にセッションを発行する。
   - 通常画面および設定系 API は有効なセッションを要求する。
3. ログアウト
   - `POST /logout` でセッションを破棄し、ログイン画面へ戻す。

## セッション設計

- セッショントークンは乱数 32 文字の 16 進文字列とする。
- cookie 名は `mr_session` とする。
- cookie には `Path=/`、`HttpOnly`、`SameSite=Strict` を付与する。
- 有効期限はメモリ上で 15 分とし、アクセス時に延長する。

## 制限事項

- セッションは 1 つのみ保持するため、多端末同時利用では後勝ちになる。
- HTTP のままなので通信路保護は行わない。
- 初期 AP パスワードが既知である問題自体は別課題として残る。
