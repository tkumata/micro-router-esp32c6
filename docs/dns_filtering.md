# DNS フィルタリング機能 - アーキテクチャと実装詳細

## 1. 概要

本プロジェクト (Phase 8) では、ドメインレベルでの広告・トラッキングブロック機能を実装しました。これは AdGuard Home や Pi-hole のような機能をマイコンレベルで実現するものです。

### 主な機能

- **DNS クエリのインターセプト**: UDP Port 53 へのパケットを捕捉
- **ブロックリスト照合**: `domain.txt` に基づくドメインフィルタリング
- **ブロック動作**: ブロック対象には `0.0.0.0` を返却
- **統計情報**: Web UI での総クエリ数、ブロック数、許可数の表示
- **Web UI 統合**: ブロックリストのアップロード、機能の ON/OFF 切り替え
- **不揮発性設定**: 設定の保存と再起動後の復帰

---

## 2. アーキテクチャ

### DNS Proxy 方式

```
AP Client (192.168.4.x)
  ↓ UDP Port 53
ESP32C6 (192.168.4.1) [DNSFilterManager]
  ├─ DNS クエリを受信
  ├─ ドメイン名を抽出
  ├─ ブロックリスト (メモリ上) と照合
  ├─ [ブロック対象] → 0.0.0.0 を返答 (Aレコード)
  └─ [許可対象] ──→ 上流 DNS (8.8.8.8) に転送
                    │
                    ▼
              上流 DNS サーバー
```

### キャプティブポータル機能

未設定時やインターネット接続がない場合、すべての DNS クエリに対して自分自身の IP アドレス (`192.168.4.1`) を返すことで、ユーザーを強制的に設定画面へ誘導します。

## 3. 実装詳細

### 3.1 DNSFilterManager クラス

DNS フィルタリングの中核となるクラスです。

- **`begin()`**: UDP ポート 53 を開き、ブロックリストを読み込みます。
- **`handleClient()`**: `loop()` 内で呼び出され、DNS パケットを処理します。
- **`loadBlocklistFromFile()`**: LittleFS から `domain.txt` を読み込み、メモリ上のバッファに展開します。
- **`isBlocked()`**: ドメインがブロックリストに含まれているか判定します。完全一致およびサブドメイン一致に対応しています。

### 3.2 メモリ管理 (最適化)

ESP32C6 のメモリリソースを有効活用するため、以下の最適化を行っています。

1. **単一バッファリング**:
   `std::vector<String>` を使うと大量のヒープ断片化が発生するため、`char* blocklistBuffer` という単一の巨大なバッファ (デフォルト 128KB) を確保し、そこに全ドメイン文字列を詰め込んでいます。
2. **ポインタ配列**:
   `std::vector<const char*>` で各ドメインの開始位置へのポインタのみを管理します。

### 3.3 ブロックリストの更新フロー

Web UI からのファイルアップロードは、メモリ不足を防ぐためにストリーム処理で実装されています。

1. Web UI から `multipart/form-data` で `domain.txt` を POST
2. `WebUIManager` が受信データを `blocklist.txt.tmp` にストリーム書き込み
3. アップロード完了後、既存の `blocklist.txt` を `.bak` にリネーム
4. `.tmp` を `blocklist.txt` にリネーム
5. `DNSFilterManager` が新ファイルをリロード

## 4. データフォーマット

### domain.txt

- **形式**: 1 行 1 ドメイン
- **コメント**: `#` で始まる行は無視
- **空行**: 無視
- **hosts 形式互換**: `0.0.0.0 domain.com` の形式も自動的にパースして対応

**例**:

```text
# 広告配信サーバー
ads.google.com
doubleclick.net

# トラッキング
analytics.google.com
```

### ブロックリストの生成

同梱の `tools/convert_adblock_to_domains.py` を使用して、一般的な Adblock Plus 形式 (豆腐フィルタなど) から `domain.txt` を生成できます。

---

## 5. 制限事項

- **最大ドメイン数**: メモリ制限により、概ね 5,000 ドメイン程度を推奨 (バッファサイズ 128KB 依存)
- **HTTPS フィルタリング**: ドメインレベルでのブロックのみ可能 (URL パスベースのブロックは不可)
